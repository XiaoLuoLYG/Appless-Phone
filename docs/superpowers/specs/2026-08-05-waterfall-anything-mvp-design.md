# Waterfall Anything 初版 Demo 设计

日期：2026-08-05

状态：设计已确认；仅形成规格，尚未实现

## 目标与非目标

Waterfall Anything 是 AIPhone 内独立的媒体发现体验。初版从现有 `media.aggregate.search` 结果进入，在同一个 HTML 页面切换为手机全屏、单条、纵向滑动的有限内容流，并为每条内容给出可核对的简短推荐理由。

目标：

- 用一个可复用的候选编排器，对统一候选做确定性去重、排序和来源均衡；
- 用媒体适配器复用现有视频、帖子和 HTML 渲染字段；
- 保留现有聚合搜索页作为入口，增加“进入发现流”；
- 让来源开关立即在本地重排，不重新请求 provider；
- 让餐饮、出行后续只需映射到同一最小候选字段即可复用编排器。

非目标：

- 不接管主 Agent、现有检索工具、业务页面、App 路由或导航；
- 不新增模型、依赖、数据库、行为持久化、异步 Agent、自然语言输入或无限加载；
- 不修改 provider 调用、授权逻辑和 `sourceStatuses` 错误事实；
- 不实现餐饮、出行适配器，不建立接口、工厂或插件体系；
- 不重构现有聚合搜索页、A2UI 链路或 HTML 渲染框架。

## 真实现有代码事实

本规格以 2026-08-05 当前 working tree 为起点；其中已有用户未提交的聚合搜索修复，包含 X `messageText` 正文映射和隐藏 `result N` 占位标题。后续实现必须保留这些修复。

- `AggregateSearchClient.ets` 的 `callAggregateSearch()` 聚合 YouTube、B 站、X、Hacker News、Reddit 和知乎；当前调用结束后返回一次完整结果。
- `AggregateSearchTypes.ets` 将结果分为 `videos`、`posts`、`sourceStatuses`。视频已有来源、标题、摘要、原始链接、封面、发布时间和时长；帖子已有来源、标题、正文、原始链接、发布时间及扩展 `rows`。
- 当前去重只在视频列表和帖子列表内部按 URL（无 URL 时按 ID）分别执行，没有跨类型去重、相关性排序或来源打散。
- `AggregateSearchA2ui.ets` 把结果写入 `/aggregateSearch`；`HtmlHomeSnapshot.ets` 再映射为 `aggregate-video`、`aggregate-post` 和 `aggregate-source-status`。
- `HtmlAggregateSearchHomeRenderer.ets` 已生成独立 HTML 文档，按“视频 / 讨论”分区，已有类型与来源筛选、视频 iframe、帖子图片、元数据和原文链接；筛选完全在页面内 JavaScript 执行。
- `HtmlHomeRenderer.ets` 已按 `document.kind === 'aggregate-search'` 选择上述渲染器。因此发现流可在这份 HTML 内切换模式，无需新增页面路由。

## 三层架构

### 1. 候选编排器内核

一个无副作用的本地函数。输入为查询词、统一候选列表、来源开关、批次数量，以及预留但初版不解析的 `preferenceDescription`；输出为排好序的下一批候选和每条推荐理由。

它不读取网络、存储或用户历史，也不认识媒体、餐饮、出行业务对象。初版来源开关是唯一可执行的轻量偏好规则；`preferenceDescription` 固定为空字符串，仅保留第二阶段输入位置。

### 2. 媒体适配器

把现有 `AggregateSearchVideo` 和 `AggregateSearchPost` 直接映射为候选，不改变 provider 数据：

| 候选字段 | 视频映射 | 帖子映射 |
| --- | --- | --- |
| `id` | 原 `id` | 原 `id` |
| `source` | 原 `source` | 原 `source` |
| `mediaType` | `video` | 有图片为 `image_text`，否则为 `post` |
| `title` | 原 `title` | 非占位的原 `title` |
| `summary` | 原 `summary` | 原 `text` |
| `url` | 原 `url` | 原 `url` |
| `coverUrl` | 原 `thumbnail` | `rows` 中 `mediaurl/image/images/thumbnail/cover/pic/picture` 的第一条有效 URL |
| `publishedAt` | 原 `publishedAt` | 原 `publishedAt` |
| `originalIndex` | 当前结果顺序 | 接在视频后的当前结果顺序 |

初版只增加这一种映射函数；未来餐饮、出行使用普通函数产出同一字段，不为单个实现建立抽象层级。

### 3. 沉浸式全屏发现流

扩展现有聚合搜索 HTML：入口态保留当前页面；点击“进入发现流”后，用同一文档内的容器显隐和样式状态进入全屏模式。内容区使用原生 CSS 纵向 `scroll-snap`，每屏一条，不引入手势库。

- `video`：复用现有封面、iframe 和原始链接；
- `image_text`：封面为主视觉，叠加标题与摘要；
- `post`：以正文、来源和时间为主，保留原文链接；
- 固定轻操作只有返回、来源偏好、推荐理由；内容自身继续使用现有播放或原文链接能力。

## 数据流

```text
现有 media.aggregate.search
  -> AggregateSearchResult（videos / posts / sourceStatuses）
  -> 媒体适配器（只读映射）
  -> 统一候选
  -> 候选编排器（过滤、去重、排序、理由）
  -> 当前 HTML 的发现流容器
```

`sourceStatuses` 继续由入口页展示，不进入候选流。来源切换只把同一批候选和新开关重新传给编排器，不调用工具，不刷新 A2UI surface。

## 规则排序细节

排序必须稳定且可复现，按以下顺序执行：

1. **来源过滤**：移除已关闭来源；空链接或非 HTTP(S) 链接不进入发现流，但仍保留在原聚合页。
2. **查询相关性**：查询、标题、摘要统一去首尾空白并做英文小写化；查询词只按空白和常见标点切分，无切分边界时只使用完整短语。完整查询短语命中或全部查询词命中为“强相关”，命中部分查询词为“相关”，否则为“弱相关”。同档内依次比较标题命中词数、摘要命中词数。
3. **新鲜度**：可解析时间按 `24 小时内 / 7 天内 / 30 天内 / 更早` 四档；缺失、无效或未来时间不获得新鲜度优势。
4. **链接级去重**：URL 去片段，协议和主机转小写，保留路径与查询参数；同一规范链接只保留相关性更高、更新、原始顺序更靠前的一条，跨视频和帖子生效。
5. **来源均衡**：逐条选取时先比较相关性档，再优先当前批次已出现次数更少的来源，然后比较新鲜度、命中词数和 `originalIndex`。不开随机数，不改变来源内容。
6. **批次输出**：取调用方要求的数量；初版调用方传入本次所有有效候选，因此结果是有限流，到底后不隐式抓取更多内容。

推荐理由只描述实际参与排序的机械信号，最多两项，例如“标题命中查询 · 24 小时内发布”或“相关内容 · 补充 Reddit 来源”。没有时间或命中证据时不得生成对应理由。

## 交互状态

| 状态 | 行为 |
| --- | --- |
| `entry` | 显示现有聚合搜索页；至少一条有效候选时显示“进入发现流” |
| `discovering` | 全屏显示一条内容；纵向滑动切换，页面内记录当前候选 ID |
| `source_preferences` | 覆盖层切换来源；关闭后立即本地重排 |
| `reason_open` | 当前条目上展开确定性推荐理由，再次点击收起 |
| `exhausted` | 显示“本次结果已看完”，可返回或调整来源，不自动请求 |

来源重排后，当前候选仍有效则保持当前位置；否则显示新顺序第一条。返回入口恢复进入发现流前的页面滚动位置和筛选状态。所有状态只存在当前 HTML 内存中，离开页面或获得新搜索结果即丢弃。

来源偏好默认开启所有拥有有效候选的来源，面板也只列出这些来源；失败或无候选来源继续留在入口页状态摘要中。

## 错误与空态边界

- 所有 provider 都无候选：不显示入口按钮，沿用现有空态和 `sourceStatuses`。
- 部分 provider 失败或需授权：成功来源仍可进入发现流；失败状态不伪装成内容卡。
- 用户关闭全部来源：停留在来源偏好空态并提示“至少开启一个来源”，不自动替用户开启。
- 候选缺封面：使用现有纯色/文字布局，不生成假图；缺摘要时只显示标题；缺时间时不展示新鲜理由。
- 视频嵌入失败：保留原始链接供用户打开，不宣称播放成功。
- 原始链接无效：该条不进入发现流，原聚合页和 provider 状态不受影响。
- 本次有限候选耗尽：进入 `exhausted`，不新增网络分页、缓存或后台预取。

## 最小验证方案

1. 在现有聚合搜索单测附近增加一个纯函数检查，覆盖稳定排序、强/弱相关、新鲜度、跨类型 URL 去重、来源均衡、来源关闭和理由事实。
2. 在现有 HTML renderer 测试中覆盖视频、图文、帖子映射，确认占位标题不回归，并验证入口、同页模式切换、三项轻操作和本地来源重排脚本存在。
3. 验证空候选、全部来源关闭、缺封面/时间、部分 provider 失败和嵌入失败边界；不为该功能引入新测试框架。
4. 用真实 `media.aggregate.search` 查询在 HarmonyOS 真机验收：入口页未回归、全屏单条滑动可见、来源切换不产生新工具调用、原始链接可打开、provider 错误如实保留。构建成功不能替代 Hypium 断言结果和真机可见证据。

## 第二阶段边界

技术概念统一称为“对话式推荐共创”，用户体验名称为“随聊随变”，不称“自然语言纠偏”。

第二阶段可以把独立发现流内的对话输入转换为临时、结构化偏好，再交给同一个候选编排器重排；初版仅预留 `preferenceDescription`，不展示输入框、不解析自然语言、不调用主 Agent、不持久化描述。模型、异步 Agent、长期行为画像、数据库，以及对餐饮/出行的真实适配，都必须在初版真机验证后另行设计和批准。

## 初版实现范围原则

三层是职责边界，不是三个框架。实现时优先在现有聚合结果映射与 `HtmlAggregateSearchHomeRenderer.ets` 中复用字段、HTML、筛选和链接安全逻辑；只新增一个最小纯编排函数及对应检查，不进行未请求重构。
